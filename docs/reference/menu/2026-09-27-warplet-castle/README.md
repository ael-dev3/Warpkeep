# Warplet castle menu — 2026-09-27

The Alpha 0.4 local menu uses Warplet's Watch v2 as a real-time 3D scene. The original combined model came from the [Warpkeep-Assets release](https://github.com/ael-dev3/Warpkeep-Assets/releases/tag/warplets-watch-castle-2026-09-14). To let each account have its own rooftop Warplet later, the runtime keeps the castle and guardian in separate files:

The extractor is [`scripts/assets/derive-warplet-castle-base.py`](../../../../scripts/assets/derive-warplet-castle-base.py). It accepts only the exact combined release GLB with SHA-256 `2ab3f39cae142f0e168242095ce17b9608998d26384d91609c8084956ddae6a6` and writes `docs/reference/menu/2026-09-27-warplet-castle/warplet-castle-base-v2-18428728949eea8b.glb` (3,274,996 bytes, SHA-256 `18428728949eea8b593e2920240f467609c925cf78a28eceb60a929aebc6e7c6`). The banner-texturing script then replaces only the castle's `Castle / Violet` embedded image. The original nine meshes retain identical position, normal, and index data. The base is an extraction master outside `public/`; the banner-textured GLB is the runtime castle. The standalone guardian sits on the castle turret with a +12 world-Y translation. Preserve that seating contract for replacement models, or add an explicit per-model transform instead of changing the camera to compensate.

Ael supplied the new 1254×1254 transparent PNG on 2026-09-27 and explicitly replaced the earlier emblem. Its exact 1,486,312 source bytes are preserved in both repositories. [`scripts/assets/texture-hegemony-banners.py`](../../../../scripts/assets/texture-hegemony-banners.py) deterministically composites the new emblem's alpha onto the existing violet fabric texture and embeds that texture in the castle GLB. It adds no floating plaque or extra geometry; the mark moves with the native banners. The same exact PNG appears in the menu heading. Neither the scene nor CSS reconstructs a lookalike emblem. The earlier opaque emblem is historical and is not included in the 0.4 runtime.

[`menuWarpletRegistry.ts`](../../../../src/components/menu/menuWarpletRegistry.ts) maps a *verified numeric Farcaster FID* to the guardian URL. FID `539854` is currently assigned Ael's Warplet using the [public Warpcast lookup for `0xael.eth`](https://api.warpcast.com/v2/user-by-username?username=0xael.eth). Anonymous web visitors see the same model as a showcase. Other verified FIDs receive a neutral 3D rooftop figure until their own model has been authored, reviewed, and entered in the registry. The menu accepts the authenticated Farcaster identity or a current server-verified PTR authority. It never assigns from a display name, profile image, or unverified Mini App host context. Conflicting verified FIDs fail to the neutral figure. Its scene key remounts the 3D world on account switch so one player's model cannot remain visible for the next account.

To assign another player, export an individually reviewed GLB with a compatible origin and authored animation clips, place it under `public/models/menu/`, document provenance and its exact hash in `ASSETS-LICENSE.md` and `scripts/verify-runtime-assets.mjs`, then add its numeric FID and URL to the registry. The current renderer plays `Warplet_Idle` continuously and `Warplet_Torch_Salute` occasionally when those clips exist. The camera remains fixed; movement comes from the models, fires, birds, guards, worker, and rabbit. It pauses when the menu is inactive and freezes under reduced-motion preference. The scene is decorative and does not affect gameplay authority.

The score is the owner-supplied [`Mesure Avancée.m4a` derivative](../../audio/2026-09-27-mesure-avancee/README.md). The local development menu labels itself 0.4.0; the packaged release version stays at the currently sealed 0.3.43 until the separate 0.4 release process is ready.
