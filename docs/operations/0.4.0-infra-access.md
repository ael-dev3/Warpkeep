### Read the reported failure stage

The fixed Linux caller emits only a bounded failure code and phase. Use the
phase to narrow inspection; it does not prove a particular credential is missing.

Native G001 failures can also include a fixed `diagnostic` label. For example,
`g001-materialization` identifies the credential-free build, whereas
`g001-credential-descriptor` identifies opening the private credential after
authority refresh. Labels also distinguish host, source, closure, private roots,
prepared verification, observation, receipt and cleanup. They never include raw
exceptions, paths, provider responses or credential values. A label names the
failed stage; it does not prove a missing credential, rollback or lack of effects.

| Phase | Investigate first |
| --- | --- |
| `input` / `runtime` | Supported operation, matching job, runner/UID, environment and pinned executable. |
| `source` / `bundle` | Exact current main, clean authenticated bytes, compiler-input ancestry and complete generated family. |
| `workflow` | Construction of workflow authority: exact completed Verify, job evidence and required private inputs. Inspect the actual prerequisite; do not infer it from the phase alone. |
| `operation` | The selected operation function was entered. It may still be validating evidence or may have submitted work. Reconcile through that lane's existing private journal/continuation and supported readback before retrying. |
| `result` | The operation returned but its public result or subsequent attestation failed. Treat provider effects as unresolved until the supported reconciliation establishes them. |

Keep raw provider errors, credential material and private records private. A
sanitized failure is not proof of rollback, and a successful preflight is not
proof of deployment or mutation authority.

The protected Actions checkout is intentionally detached at the selected main
SHA. Native G001 readers use `attestPolicySource` to verify clean source bytes,
the matching `origin/main` commit and their operator. Do not route them through
the historical bootstrap checker that requires a local branch named `main`.
That mismatch rejects the checkout before a session or provider request exists.
Workflow duration alone does not establish that either census sample was taken:
materialization also takes time. Only authenticated retained census records and
the supported result establish observation progress.
