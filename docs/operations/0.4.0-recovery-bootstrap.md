# 0.4.0 recovery signing bootstrap

`scripts/prepare-0.4.0-recovery-bootstrap.mjs` prepares the one dedicated,
local P-256 signing key required by the `recovery-authorization-v1` path. It
is a local filesystem operation only: it does not contact Cloudflare, GitHub,
SpacetimeDB, or any other network service. It does not deploy, provision,
enable, arm, or upload a secret.

The command is fail-closed. Calling it without `--generate` creates nothing
and returns `RECOVERY_BOOTSTRAP_GENERATION_REQUIRED`.

```powershell
node scripts/prepare-0.4.0-recovery-bootstrap.mjs --generate
```

The default private root is:

```text
%USERPROFILE%\.warpkeep\private\release-recovery-v1
```

An operator may choose a different existing-user-controlled host-private root:

```powershell
node scripts/prepare-0.4.0-recovery-bootstrap.mjs --generate --private-root C:\secure\warpkeep-release-recovery
```

The command rejects every output root in the Git worktree/repository or the
user Desktop (including OneDrive Desktop). It also rejects symbolic-link path
components. Do not put recovery material in the checkout, Desktop, build
output, CI workspace, artifact directory, or a shared sync folder.

## Files and safe output

The private root contains only these local files:

- `recovery-signing-private.jwk.json` — private P-256 JWK; never add this file
  to Git or a Worker package.
- `recovery-signing-public.jwk.json` — the derived public JWK for the checked-in
  Worker and local verifier constants.
- `recovery-signing-thumbprint.txt` — RFC 7638 SHA-256 thumbprint of that public
  JWK.

Files are created with mode `0600` and the private root with mode `0700` on
POSIX. On Windows the command also removes ACL inheritance and checks the
resulting owner-only ACL where `icacls` is available. If that check cannot be
performed, the command fails instead of accepting an unknown ACL.

Standard output is one safe JSON object: disabled state, recovery key ID
`warpkeep-0.4.0-recovery-2026-09-03-1`, local file paths, public JWK, and
thumbprint. Errors emit only a stable `RECOVERY_BOOTSTRAP_*` code. Neither
stream prints private JWK bytes or command arguments.

## Re-runs and handoff

Generation is no-clobber. If a private file already exists, it is never
rewritten; the command derives the public values from that local private key,
then either validates existing public files byte-for-byte or creates only a
missing public file. Mismatched, symbolic-link, non-regular, or insecure
existing files fail closed.

Record only the public JWK and thumbprint in the checked-in Worker and local
verifier constants. Before any signer configuration, independently derive the
public JWK and thumbprint from the local private file and require exact equality
with those pinned constants. Keep the signer disabled until the separate,
approved recovery arming procedure is complete.
