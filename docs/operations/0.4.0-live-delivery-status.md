necessary changes to the release architecture. Earlier instructions in planning
documents limiting work to local preparation or requiring the unavailable old
Mac are superseded for this delivery. Existing production data, authenticated

  `ael-dev3/Warpkeep`. The frontend uses **GitHub Pages**, with custom domain
  `warpkeep.com`; it is not a Cloudflare Pages project.

  an empty list there does not show that the production Worker is missing.
- SpacetimeDB: the configured 2.6.1 CLI lists the existing `warpkeep` database.
  Its immutable identity agrees with the auth bridge configuration. Genesis 002
  and PTR were initially absent and were created on 2026-09-04 UTC (September 5

- Worker signing, session, admin, and RPC secrets are still configured. Reading
  their names does not expose their values. Preserve managed bindings when
  uploading a new Worker version; do not recover secrets into source or logs.

The initial access checks were authenticated read observations. Two new private
database modules have since been deployed. The complete 0.4.0 release, auth
bridge changes, PTR owner provisioning, and frontend activation are not shipped.
