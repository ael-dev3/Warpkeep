### Keepalive definition and recovery

Use the existing per-user task `Warpkeep Runner Keepalive`, rather than creating
another indefinite process. Its fixed action is
`C:\Windows\System32\wsl.exe -d WarpkeepRunner -u warpkeep --exec /usr/bin/sleep infinity`.
It runs as interactive, non-elevated `heyas`, hidden, with `IgnoreNew`, three
failure restarts one minute apart, battery operation allowed and `WakeToRun=false`.
The logon trigger remains; one time trigger repeats every five minutes without
an end boundary or repetition duration. `StartWhenAvailable=true` permits catch-up;
the task execution limit is `PT0S`.

On September 12, runner ID 22 was offline while `WarpkeepRunner` was absent from
the running distro list. The task was Ready with a September 11 exit code 1;
that alone does not establish why it exited. Starting the existing task reopened
the guest and its healthy enabled service. The definition was then corrected as
above. After confirming GitHub was idle, a temporary 60-second guest hold allowed
a controlled task restart at **13:20:18 UTC**, so the new instance used the new
definition. The first repeat at **13:20:26 UTC** left that instance and its child
unchanged, with no duplicate. Task state remained Running despite LastTaskResult
changing to `0x800710E0` at the overlapping trigger; inspect the instance, service
and GitHub together instead of interpreting that field alone. The temporary
holds subsequently expired, with no matching hold process remaining and GitHub
still online/idle. This observation does not establish future availability.

To reconcile the existing definition idempotently, preserve its action,
principal and other settings. This accepts only its known logon/time triggers:

```powershell
$wkKeeper = Get-ScheduledTask -TaskName 'Warpkeep Runner Keepalive' -ErrorAction Stop
if ($wkKeeper.Actions.Count -ne 1 -or
    $wkKeeper.Actions[0].Execute -ine "$env:WINDIR\System32\wsl.exe" -or
    $wkKeeper.Actions[0].Arguments -cne '-d WarpkeepRunner -u warpkeep --exec /usr/bin/sleep infinity' -or
    [int]$wkKeeper.Principal.LogonType -ne 3 -or [int]$wkKeeper.Principal.RunLevel -ne 0) {
    throw 'Unexpected keepalive action or principal; reconcile its identity first.'
}
$wkLogon = @($wkKeeper.Triggers | Where-Object { $_.CimClass.CimClassName -eq 'MSFT_TaskLogonTrigger' })
$wkTime = @($wkKeeper.Triggers | Where-Object { $_.CimClass.CimClassName -eq 'MSFT_TaskTimeTrigger' })
if ($wkLogon.Count -ne 1 -or $wkTime.Count -gt 1 -or
    @($wkKeeper.Triggers).Count -ne ($wkLogon.Count + $wkTime.Count)) {
    throw 'Unexpected keepalive triggers; inspect before changing the task.'
}
$wkRepeat = if ($wkTime.Count -eq 1) { $wkTime[0] } else {
    New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(5) `
        -RepetitionInterval (New-TimeSpan -Minutes 5)
}
$wkRepeat.Repetition.Interval = 'PT5M'
$wkRepeat.Enabled = $true
$wkRepeat.Repetition.Duration = $null
$wkRepeat.Repetition.StopAtDurationEnd = $false
$wkRepeat.EndBoundary = $null
$wkRepeat.ExecutionTimeLimit = 'PT0S'
$wkKeeper.Settings.ExecutionTimeLimit = 'PT0S'
$wkKeeper.Settings.StartWhenAvailable = $true
$wkKeeper.Triggers = @($wkLogon[0], $wkRepeat)
Set-ScheduledTask -InputObject $wkKeeper -ErrorAction Stop | Out-Null
```

Read the stored definition back before starting it: verify both triggers, an
enabled five-minute timer, absent duration/end boundary, `StopAtDurationEnd=false`,
unlimited execution and all preserved settings above. Explicitly set
`StopAtDurationEnd`; the local trigger constructor initially supplied `true`.
[Microsoft documents `PT0S` as unlimited](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-executiontimelimit)
and [omitted repetition duration as indefinite](https://learn.microsoft.com/en-us/windows/win32/taskschd/repetitionpattern-duration).

Definition updates [do not affect an already running instance](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/set-scheduledtask).
To replace an instance still using old settings, first verify the runner is idle
and no native preparation, recovery or unresolved deployment is active. Hold the
guest briefly while restarting only the scheduled task:

```powershell
$wkHold = Start-Process -FilePath "$env:WINDIR\System32\wsl.exe" `
    -ArgumentList @('-d', 'WarpkeepRunner', '-u', 'warpkeep', '--exec', '/usr/bin/sleep', '60') `
    -WindowStyle Hidden -PassThru
```

Confirm this temporary command reached the guest and remains alive before
proceeding; if it failed, leave the existing keeper running. Then:

```powershell
Stop-ScheduledTask -TaskName 'Warpkeep Runner Keepalive'
Start-ScheduledTask -TaskName 'Warpkeep Runner Keepalive'
```

Confirm a new owned keeper instance, the enabled active service and GitHub
online/idle; check that the temporary `$wkHold.Id` exits after its bounded hold.
Do not terminate the distro or an unrelated process during this handoff.

This recovers an exited keeper while the user is logged in. A running sleep
process is not runner health: [IgnoreNew](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-multipleinstances)
prevents duplicate instances but cannot repair an unhealthy service behind a live
keeper. Catch-up after missed schedules [can have a ten-minute default delay](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-startwhenavailable);
five-minute repetition is not a recovery deadline. The task does not wake Windows
or run before interactive logon. Use only `WarpkeepRunner` for current maintenance.

   binding and release-specific authorization state. Checked-in
   [signer configuration](../../services/release-recovery/wrangler.signer.toml)

   the workflow obtains and persists its verified claim for the exact run.
4. Successful `Verify` for a push of the selected current protected `main`,
   classification into `sealed-g002-recovery`, exact artifact attestation,
