# Warpkeep 0.4.0 Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair and harden PR #228 into a green, inert preparation release for permanent Genesis 001 preservation, sealed Genesis 002, and owner-only PTR.

**Architecture:** Keep PR #228 as the single preparation PR. Fix hosted verification without weakening production contracts, preserve the exact Genesis 001 source projection while proving future-release routes are sealed, give Genesis 002 a disjoint administrator audience, bind PTR provisioning to the configured owner and live auth epoch, and retain the selector as a pure three-realm directory. The preparation merge must remain version `0.3.43` and must not deploy Pages.

**Tech Stack:** TypeScript, Vitest, SpacetimeDB 2.6.1 TypeScript modules, Cloudflare Workers/Wrangler 4.110.0, GitHub Actions, Node 22.22.3, npm 10.9.8, pnpm 11.7.0.

**Spec:** `docs/superpowers/specs/2026-08-30-warpkeep-0.4.0-sealed-realms-release.md`

## Global Constraints

- Genesis 001 remains exact `0.3.43`, preserves existing players, and never accepts another admission or realm mutation.
- Genesis 002 remains release `0.4.0`, zero-population, private, non-connectable by players, and has no admission surface.
- PTR remains release `0.4.0-ptr.1`, has exactly one configured human owner, and no public admission surface.
- Hermes is a non-player operations principal; its G002 and PTR tokens use distinct audiences and cannot act as player tokens.
- The root package and lock remain `0.3.43` throughout this preparation plan.
- `config/releases/0.4.0-sealed-launch.json` remains inert: null operational evidence, `pagesDeploymentApproved: false`, and all presentation/notification gates false.
- Do not weaken the macOS BSD filesystem, codesign, secret, protected-main, receipt, identity, or ambiguous-outcome production contracts.
- Preserve the required GitHub contexts `verify`, `auth-bridge`, `spacetimedb-module`, `analyze`, and `CodeQL`.
- Use exact full SpacetimeDB identities in production; never activate an alias or a value that collides with Genesis 001.
- Never print raw secrets, owner FIDs, private census data, private receipt bodies, or CLI token contents.
