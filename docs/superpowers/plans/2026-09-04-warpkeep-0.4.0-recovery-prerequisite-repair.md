# Warpkeep 0.4 Recovery Prerequisite Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Repair the local recovery-authorization foundations so the later route-less signer stays fail-closed, restart-safe, and unable to activate a release without authoritative evidence.

**Architecture:** Preserve the existing v1 Durable Objects and introduce an isolated v2 class and namespace. V2 durably preserves the exact GitHub metadata commitment required for no-archive claim rechecks, exposes only a signer-private claimed-row projection, and owns read-only post-deadline reconciliation. The realm observer accepts only strict injected pins and fixture bytes; it has no production-success path until independently generated inputs exist.

**Tech Stack:** TypeScript 7, Cloudflare Workers/Durable Objects SQLite, Vitest 4, @cloudflare/vitest-pool-workers, Web Crypto, the existing GitHub App read-only client, and the strict RawModuleDef-v10 parser.

**Spec:** docs/superpowers/specs/2026-09-03-warpkeep-0.4.0-recovery-authorization.md; amendment to docs/superpowers/plans/2026-09-03-warpkeep-0.4.0-recovery-service.md Tasks 4-6.

## Global Constraints

- Do not deploy, provision, upload secrets, alter DNS, push, merge, dispatch a workflow, or activate recovery as part of this plan.
- RECOVERY_ENABLED stays false unless a later operator-only materialization gate validates all three generated realm fixtures, their manifest, and the toolchain record. Guessed values, live fallbacks, and permissive stubs cannot make it true.
- Preserve v1 objects. The v2 signer receives no v1 binding and never reconstructs a v1 authorization from a live GitHub read, retained JWS, or process cache.
- Never read, copy, hash, log, or expose Spacetime program_bytes. Never put raw OIDC, authorization JWS, GitHub App credential, RPC credential, private JWK, FID, receipt, archive body, or private-root artifact in Git, logs, errors, workflow outputs, or public responses.
- The historical G001 receipt remains unavailable and is never synthesized. Expected SHA-256: 5a9629c7ee695abc2b2369921274dcaa9c618b747387b90f9444429ab8e81d63.
- Local deployment verification remains nbf <= now < exp. A separate signer-private correlation path may accept a signed receipt only while now < claimDeadline.
- At or after claimDeadline, only the v2 Durable Object alarm can reconcile its stored consumed row. No public reconcile route, later workflow attempt, receipt, or fresh OIDC token gets reconciliation or deployment authority.
