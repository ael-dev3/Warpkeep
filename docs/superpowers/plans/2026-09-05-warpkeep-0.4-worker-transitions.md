# Warpkeep 0.4 Worker Transitions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement deterministic Worker journey timing and recall for the real 0.4 backend adapter.

**Architecture:** A pure immutable journey value captures dispatch-time effects and route length. Functions derive current phase and return earnings, or create a recalled return plan. The database adapter, not these functions, authorizes routes/owners, reserves capacity and consumes completed assignments exactly once.

**Tech Stack:** Existing TypeScript/bigint/Vitest, pinned local Node22.22.3, no dependencies.

**Spec:** `docs/superpowers/specs/2026-09-05-warpkeep-0.4-gameplay-design.md`, Worker transition boundary contract.

## Global Constraints

- Leave every frozen G001 source projection and persistent row intact.
- Import no live G001 schema, Worker authority, or Inner Keep authority into the new core.
- Use integer microsecond server timestamps and checked integer resource arithmetic.
- Resources become spendable on return, not from an optimistic client estimate.
- Pure functions are not authorization; no caller may bypass actual server topology or identity checks using these exports.
- No backend/dependency/deployment/admissions changes in this task.

## Task 1: Checked immutable journey transitions

**Files:** Create `spacetimedb/gameplay04/workerJourney.ts` and `tests/gameplay04WorkerJourney.test.ts`.

**Consumes:** `Resource04`, `CompletedLevels04`, `requireGatherDuration04`, `gatheringYield04`, `travelPerEdge04`, `GAMEPLAY04_GATHER_QUANTUM_MICROS` from `./policy`. Policy review must be accepted before dispatch.

**Produces:**

```ts
type Journey04 = Readonly<{
  resource: Resource04;
  dispatchedAt: bigint;
  routeEdges: number;
  travelPerEdgeMicros: bigint;
  gatheringDurationMicros: bigint;
  yieldPerQuantum: bigint;
  recalledAt: bigint | null;
}>;
type JourneyObservation04 = Readonly<{
  phase: 'outbound' | 'gathering' | 'returning' | 'complete';
  arrivesAt: bigint;
  gatheringStopsAt: bigint;
  returnsAt: bigint;
  earned: bigint;
  nextDueAt: bigint | null;
}>;
function dispatchJourney04(input: Readonly<{
  resource: Resource04; dispatchedAt: bigint; routeEdges: number;
  gatheringDurationMicros: bigint; completed: CompletedLevels04;
}>): Journey04;
function observeJourney04(journey: Journey04, now: bigint): JourneyObservation04;
function recallJourney04(journey: Journey04, now: bigint): Journey04;
```

Export the types/functions and `Gameplay04JourneyError` with fixed code
`GAMEPLAY04_JOURNEY_INVALID`; errors expose no raw input. Inputs are runtime
validated: exact own enumerable fields, correct bigint values, nonnegative
timestamps <= signed-i64 max, safe integer routeEdges0..8192 (two depth4096 tree
chains), allowed gather durations, valid resource. Captured per-edge timing must
be one of 2,000,000 minus level*100,000 for levels0..5; yield must be one of
10,12,14,16,18,20. Reject missing/extra fields, null/array state, invalid captured
policy and out-of-range arithmetic. Validate derived automatic return deadline
even for recalled values; never accept a malformed journey by selecting an easier
branch. `now` must be >= dispatch and >= recalledAt when present. Recall time,
if present, must be >= dispatch and strictly before automatic return start.

- [ ] **Step 3: Implement formulas after complete validation.**

```ts
const travel = BigInt(routeEdges) * travelPerEdgeMicros;
const arrivesAt = dispatchedAt + travel;
const automaticStop = arrivesAt + gatheringDurationMicros;
const stop = recalledAt === null ? automaticStop : recalledAt;
const returnTravel = stop < arrivesAt ? stop-dispatchedAt : travel;
const returnsAt = stop + returnTravel;
const gatheredUntil = now < stop ? now : stop;
const elapsedGather = gatheredUntil > arrivesAt ? gatheredUntil-arrivesAt : 0n;
const earned = (elapsedGather / GAMEPLAY04_GATHER_QUANTUM_MICROS) * yieldPerQuantum;
```

Classify in order: if now>=returnsAt complete; else if now>=stop returning;
else if now>=arrivesAt gathering; else outbound. nextDueAt is null for complete,
returnsAt for returning, stop for gathering, min(arrivesAt,stop) for outbound.
`earned` is derived cargo, not spendable balance. Complete zero-travel transitions
at the exact stop timestamp. `recallJourney04` returns the original immutable
values unchanged when already recalled, returning or complete; otherwise return
a frozen copy with recalledAt=now. `dispatchJourney04` captures numeric policy
once; later observation never reads completed buildings. Freeze every output.
Use a single internal validation/derivation helper, not copied arithmetic in
each function. Verify checked deadlines before deriving phase.
