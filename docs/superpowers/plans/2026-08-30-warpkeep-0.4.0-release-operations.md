# Warpkeep 0.4.0 Protected Release Operations Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for these sequential production operations. Use superpowers:verification-before-completion before every live-success claim.

**Goal:** Starting from the inert protected-main preparation merge, create receipt-proven sealed Genesis 002 and owner-only PTR, activate the exact three-file 0.4.0 successor, deploy it, tag it, and finish with zero open PRs.

**Architecture:** All private G001 census/monitor state and G002/PTR mutation state stays on the repository-exclusive macOS runner behind the fixed `sealed-realms-production.yml` dispatcher. Cloudflare prepared deployment uses its existing protected workflow. Every mutation is inspect/confirm/apply, every ambiguous result stops mutations until read-only reconciliation, and only a privacy-safe generated binding crosses into Git.

**Tech Stack:** GitHub Actions/CLI, protected macOS ARM64 runner, Cloudflare Wrangler 4.110.0, SpacetimeDB CLI 2.6.1, Node 22.22.3, npm 10.9.8.

**Preparation Plan:** `docs/superpowers/plans/2026-08-30-warpkeep-0.4.0-preparation.md`

**Runbook:** `docs/operations/genesis-002-sealed-launch.md`

## Global Constraints

- `S` always means the exact inert preparation squash commit on protected `main`.
- Never rerun the historical Genesis 001 freeze publisher or B0 workflow.
- Never publish repository future source to Genesis 001, relocate/deactivate its players, or mutate its admission state.
- Never expose a secret, owner FID/auth epoch, applicant row/count/raw digest, private receipt/evidence, CLI config, or private filesystem path.
- Genesis 002 and PTR publications are fresh and one-shot. A possibly submitted error requires read-only reconciliation before any new mutation.
- Genesis 002 stays zero-population/private/non-connectable. PTR gets one human owner anchor plus Hermes as a non-player operations principal.
- Do not create the activation PR until all private receipts exist and the public binding generator succeeds.
- The activation successor changes exactly `config/releases/0.4.0-sealed-launch.json`, `package.json`, and `package-lock.json`.
- Do not tag or publish a GitHub release until Pages live verification succeeds.
