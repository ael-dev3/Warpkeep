# Warpkeep 0.4.0 Recovery Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and locally verify the isolated Cloudflare recovery gateway, private signer, live-realm observer, and single-use authorization ledger required by the approved Warpkeep 0.4.0 recovery path.

**Architecture:** A narrow public gateway forwards exact requests to a route-less signer over a Cloudflare Service binding. The signer validates GitHub OIDC, independently reloads candidate/artifact and realm evidence, signs short-lived ES256 authorization and claim receipts, and serializes a server-armed one-time request plus dynamic enabled/epoch control in a SQLite Durable Object. The existing auth bridge gains only a named internal observation RPC; it never exposes recovery behavior on its public browser routes.

**Tech Stack:** Node 22, pnpm 11.7.0, TypeScript 7, Cloudflare Workers and Service bindings, SQLite Durable Objects, Web Crypto, Vitest, `@cloudflare/vitest-pool-workers`, Wrangler 4.110.0.

**Spec:** `docs/superpowers/specs/2026-09-03-warpkeep-0.4.0-recovery-authorization.md`
