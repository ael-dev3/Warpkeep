# Warpkeep 0.4.0 Recovery Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and locally verify the isolated Cloudflare recovery gateway, private signer, live-realm observer, and single-use authorization ledger required by the approved Warpkeep 0.4.0 recovery path.

**Architecture:** A narrow public gateway forwards exact requests to a route-less signer over a Cloudflare Service binding. The signer validates GitHub OIDC, independently reloads candidate/artifact and realm evidence, signs short-lived ES256 authorization and claim receipts, and serializes a server-armed one-time request plus dynamic enabled/epoch control in a SQLite Durable Object. The existing auth bridge gains only a named internal observation RPC; it never exposes recovery behavior on its public browser routes.

**Tech Stack:** TypeScript 7, Cloudflare Workers and Service bindings, SQLite Durable Objects, Web Crypto, Vitest, `@cloudflare/vitest-pool-workers`, Wrangler 4.110.0.

**Spec:** `docs/superpowers/specs/2026-09-03-warpkeep-0.4.0-recovery-authorization.md`

- Genesis 002 remains sealed with zero players/admissions; PTR remains singleton-owner-only with no general admission or request surface.
- Worker names are exactly `warpkeep-release-recovery-gateway`, `warpkeep-release-recovery-signer`, and `warpkeep-auth-bridge`; the Durable Object class is `ReleaseRecoveryAuthorizationLedger`.
- The recovery issuer is `https://release-auth.warpkeep.com`; the GitHub OIDC audience is `warpkeep-release-recovery`.
- GitHub identity is fixed to `ael-dev3/Warpkeep`, repository ID `1273513252`, owner ID `183124839`, ref `refs/heads/main`, workflow `ael-dev3/Warpkeep/.github/workflows/deploy-pages.yml@refs/heads/main`, and environment `github-pages`.
- Release version is `0.4.0`; operation is `github-pages-production-deploy`; canonical origin is `https://warpkeep.com`.
- Recovery authorization lifetime is at most 15 minutes; live evidence age is at most 120 seconds; claim-receipt lifetime is at most two minutes; claimed-row deadline is 20 minutes.
- Automatic reconciliation delays are exactly 1, 5, 15, and 60 minutes. Reconciliation never reissues, reclaims, or deploys.
- The historical G001 receipt remains unavailable with expected SHA-256 `5a9629c7ee695abc2b2369921274dcaa9c618b747387b90f9444429ab8e81d63`; no service may synthesize or write it.
