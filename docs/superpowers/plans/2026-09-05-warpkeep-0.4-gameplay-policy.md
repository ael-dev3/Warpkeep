# Warpkeep 0.4 Gameplay Policy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement the isolated, deterministic numeric policy consumed by the forthcoming 0.4 state machine and realm adapters.

**Architecture:** A dependency-free TypeScript module holds exact recipes, durations and checked integer calculations. It has no database registration, authorization substitution, client clock or G001 import. Backend and presentation consumers will use this same contract.

**Tech Stack:** TypeScript, bigint, existing Vitest, pinned local Node 22.22.3. No dependency install.

**Spec:** `docs/superpowers/specs/2026-09-05-warpkeep-0.4-gameplay-design.md`, Workers/progression and construction numeric policy sections.

## Global Constraints

- Leave every frozen G001 source projection and persistent row intact.
- Import no live G001 schema, Worker authority, or Inner Keep authority into the new core.
- Use integer microsecond server timestamps and checked integer resource arithmetic.
- Balances cap at 1,000,000 per resource.
- Maximum level is five.
- No gameplay deployment, activation, admissions or schema mutation in this subplan.
- Preserve existing unrelated working-tree changes and the root node_modules junction.

## Full-goal coverage boundary

This is the numeric-policy subproject, not a replacement for the gameplay or release objective. State transitions/receipts, persistent PTR/G002 adapters, scheduler and real atlas route/capacity validation, generated bindings, client integration and authenticated journey verification remain explicit successor work under the release-closure ledger. They consume the exports below. This subplan does not claim those requirements are complete. Its gate can reject incorrect economy arithmetic independently from backend integration.

**Interfaces:**

```ts
export type Resource04 = 'food' | 'wood' | 'stone' | 'gold';
export type Building04 = 'city-mill' | 'lumber-camp' | 'city-stoneworks'
  | 'city-goldworks' | 'city-barracks' | 'grand-covenant-cathedral';
export type Cost04 = Readonly<Record<Resource04, bigint>>;
export type CompletedLevels04 = Readonly<Record<Building04, number>>;
export const GAMEPLAY04_POLICY_VERSION = 'warpkeep-0.4-gameplay-v1';
export const GAMEPLAY04_BALANCE_CAP = 1_000_000n;
export const GAMEPLAY04_WORKER_COUNT = 4;
export const GAMEPLAY04_GATHER_QUANTUM_MICROS = 10_000_000n;
export const GAMEPLAY04_GATHER_DURATIONS_MICROS: readonly bigint[];
export class Gameplay04PolicyError extends Error { readonly code: string; }
export function buildingCost04(kind: Building04, targetLevel: number): Cost04;
export function buildingDuration04(targetLevel: number, completed: CompletedLevels04): bigint;
export function gatheringYield04(resource: Resource04, completed: CompletedLevels04): bigint;
export function travelPerEdge04(completed: CompletedLevels04): bigint;
export function requireGatherDuration04(durationMicros: bigint): bigint;
export function creditResource04(balance: bigint, earned: bigint): Readonly<{ balance: bigint; credited: bigint; overflow: bigint }>;
```

All public functions validate runtime inputs, not only TypeScript types. Reject
unknown resource/building values, missing/extra completed-level keys, noninteger
levels, completed levels outside 0..5, target levels outside 1..5, non-bigint
money/duration, negative or greater-than-u64 earned values, and balance outside
0..1,000,000. Do not coerce strings/numbers, clamp invalid input, mutate arguments,
or expose mutable nested catalog objects. Error code is
`GAMEPLAY04_POLICY_INPUT_INVALID`; no raw input is included in errors.

- [ ] **Step 3: Implement the isolated policy.**

Use exact food/wood/stone/gold base costs:

```ts
const bases = {
  'city-mill': [20n,40n,20n,0n],
  'lumber-camp': [20n,20n,40n,0n],
  'city-stoneworks': [40n,20n,20n,0n],
  'city-goldworks': [40n,60n,40n,20n],
  'city-barracks': [60n,80n,80n,40n],
  'grand-covenant-cathedral': [80n,100n,120n,60n],
} as const;
const multipliers = [1n,3n,7n,15n,31n] as const;
const buildMicros = [120n,900n,3600n,14400n,43200n].map(s => s*1_000_000n);
const gatherMicros = [60n,600n,3600n,28800n].map(s => s*1_000_000n);
const ceilBps = (base: bigint, bps: bigint) => (base*bps+9_999n)/10_000n;
```

After validation, cost = base * target multiplier per component; build duration
= ceilBps(target duration, 10,000 - Cathedral level*500); travel per edge =
ceilBps(2,000,000, 10,000 - Barracks level*500). Matching economy gathering
yield is 10 + 2*completed level per ten-second quantum. All other buildings leave
that resource's yield unchanged. Credit = min(earned, cap-balance), overflow =
earned-credit, new balance = balance+credit. Export a frozen allowed-duration
array, and use exact membership for duration validation. Keep catalog data
module-local, validate own enumerable key membership exactly and reject arrays/null.
