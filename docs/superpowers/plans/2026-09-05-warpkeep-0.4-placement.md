# Warpkeep 0.4 Placement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Preserve existing Inner Keep geometry with an isolated checked 0.4 placement contract.

**Architecture:** A pure module validates candidate and existing placements against fixed interior geometry. It exports a canonical digest-input string for later quote binding without importing G001 code or lifecycle. Database uniqueness, ownership, quote digests and project settlement remain the construction adapter's responsibility.

**Tech Stack:** TypeScript bigint, existing Vitest and local pinned Node22.22.3; no dependencies.

**Spec:** `docs/superpowers/specs/2026-09-05-warpkeep-0.4-gameplay-design.md`, Construction policy.

## Global Constraints

- Leave every frozen G001 source projection and persistent row intact.
- Import no live G001 schema, Worker authority, or Inner Keep authority into the new core.
- Keep six existing building kinds, five levels, one Builder, permanent placement.
- Upgrade retains the exact persisted transform.
- No schema, auth, deployment, admissions, dependencies or G001 file edits in this task.

## Task 1: Isolated exact placement validation

**Files:** Create `spacetimedb/gameplay04/placement.ts`, `tests/gameplay04Placement.test.ts`.

**Consumes:** `Building04` from approved `./policy` as a type-only import.

**Produces:**

```ts
export type Placement04 = Readonly<{
 kind: Building04; x: bigint; z: bigint; rotation: number;
}>;
export type PlacementResult04 = Readonly<{
 valid: boolean;
 reason: 'valid' | 'invalid' | 'off-grid' | 'rotation' | 'outside'
  | 'reserved' | 'occupied' | 'duplicate-kind' | 'invalid-state';
}>;
export const GAMEPLAY04_LAYOUT_VERSION = 'warpkeep-0.4-placement-v1';
export function evaluatePlacement04(candidate: Placement04, occupied: readonly Placement04[]): PlacementResult04;
export function placementDigestInput04(): string;
```

Coordinates are integer microunits (one meter=1,000,000), rotation is one of
0/90000/180000/270000 millidegrees. Validate exact own enumerable fields and
runtime values; null/arrays/unknown kinds are invalid. Candidate x/z must fit
signed-i64, lie on500000 grid, and footprint must stay inside support. At most
six existing placements; reject sparse arrays, malformed or individually invalid
existing placements, duplicate kinds or mutually overlapping existing placements
as invalid-state before evaluating candidate. Frozen valid outputs only; no throws
for ordinary malformed JSON-like input, no mutation, no raw input in results.
No attempt to accept Proxy/getter authority: backend creates ordinary records.

Geometry values in microunits, copied as data into the new isolated contract:

```ts
const support = [-44_000_000n,44_000_000n,-40_000_000n,32_000_000n] as const;
// Half-X, half-Z in Building04 canonical order:
const footprints = [
 ['city-mill',5_650_000n,4_750_000n],
 ['lumber-camp',5_300_000n,4_400_000n],
 ['city-stoneworks',5_500_000n,4_600_000n],
 ['city-goldworks',5_500_000n,4_600_000n],
 ['city-barracks',9_250_000n,7_750_000n],
 ['grand-covenant-cathedral',18_500_000n,16_010_000n],
] as const;
// Exclusion id, center-X, center-Z, half-X, half-Z:
const exclusions = [
 ['gate-spine',0n,14_500_000n,3_000_000n,17_500_000n],
 ['civic-commons',0n,2_000_000n,5_000_000n,5_000_000n],
 ['gate-approach',0n,30_000_000n,4_000_000n,2_000_000n],
] as const;
```

Quarter turns90/270 swap half-extents. Rectangles overlap iff both absolute
center differences are strictly smaller than summed half-extents; touching is
allowed. Support boundary equality is allowed. No tolerance/float arithmetic.
Duplicate candidate kind rejects even if candidate is elsewhere: upgrades must
use a distinct backend path that checks exact existing transform, rather than
call this new-placement API with a fabricated occupied list.
